# 消息轨迹：运行时快照节点

本次新增设计以 `dsh-context-snapshot-prototype-v6.html` 为交互参考。它延续已归档的 Open Design v5 布局，由 Codex 本地修改；Open Design 桌面连接超时，未在 Studio 中生成或同步。浏览器访问本地文件被策略阻止，尚未完成视觉验收。随后已按用户确认实现于插件；真实浏览器视觉验收仍待完成。

## 展示

运行时快照使用琥珀色卡片，与蓝色轮次、绿色压缩摘要、灰色系统消息区分。使用芯片图标和“运行时快照”标题，让颜色成为辅助标识。浅色背景 `#fff8e9`、边框 `#ead2a3`、左侧强调线 `#bb811d`、正文 `#664519`；深色模式见原型 `.runtime-node` 样式。

标题行展示最新或历史标记，以及记录所属轮次/位置。正文只显示该条记录的摘要，默认最多两行。底部显示该记录的上下文项数。摘要未生成时显示“摘要生成中”；不可用时使用该条原文的截取并标明“原文摘录”，不能借用最新快照的摘要填充历史记录。

## 位置与状态

- 快照是独立节点，轮次收起时仍可辨识。发生于轮内的快照应在对应轮次容器中保留可见摘要，展开后按实际消息位置显示，不能统一挪到轮首或轮尾。
- 原型默认演示压缩后新增快照，位于最新轮次上方；标注“第 2 轮之后”，避免误读为第 2 轮开头。轮次倒序只用于浏览；模型消息位置由现有 surface 投影确定，不能单凭 seq 排序。
- 同轮允许多条快照。“最新快照”只标记最新有效快照；旧快照如果仍在当前模型上下文中，可以保留并标记历史。
- 新快照不会直接删掉旧快照；仅当真实 replacement 移除旧来源时，旧节点退出当前上下文，与绿色压缩摘要衔接。不能在 compaction/start 时提前删除。
- 清除事件显示“运行时上下文已清除”，不沿用之前的摘要。它是独立状态，不能因缺少 snapshot sections 而漏掉。

## 动效与复用

新提交快照到达时，使用 650ms 淡入和 5px 位移，配合一次淡琥珀色边缘高亮。首次加载、重连及切换标签不播放到达动画。尊重 prefers-reduced-motion。原型卡片上的“演示快照到达”按钮仅用于验收，不能进入产品。

复用 `.runtime-node*` 样式和 `runtimeNode()` 模板，将样例摘要、项数、轮次和 seq 替换为实际记录。所有产品文案接入现有多语言字典。原型保留原有压缩回放演示；未完整模拟每种生产状态。实现前应核对逐条摘要缓存是否存在，以记录身份绑定摘要，防止显示错配。
